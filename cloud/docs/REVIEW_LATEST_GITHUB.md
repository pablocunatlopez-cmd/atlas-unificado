# Revisión e integración de Atlas

Fuente confirmada por el propietario: pablocunatlopez-cmd/atlas-unificado, main hasta da68eaa. Se conservan los cambios anteriores de Sites y se incorporan memoria por ámbitos y habitantes, carta de evolución, evidencias tipadas, sesiones de participación y exportación STL.

Los enlaces de AI Studio y Grok no devolvieron contenido accesible. El propietario confirmó que el código actualizado también está en este GitHub; no se atribuye a esos enlaces ninguna inspección ni integración no realizada.

## Correcciones de esta integración

- ERAS queda definido como motor gráfico del cuerpo de Lía, dentro de Ion. El juego original se conserva como aplicación y banco de pruebas del motor.
- El editor abre escenas con módulos reales de ERAS: render WebGPU/WebGL2, iluminación y materiales. Las 17 copias tienen hashes y procedencia; scripts/sync-eras-engine.mjs comprueba su correspondencia con el origen.
- Las nuevas escenas del editor usan la cola del modelo, mientras los ajustes de configuración conservan el plan autoral, materiales y cámara. El HTML editado permanece en su vista aislada y se conservan versiones.
- Música y guiones se recuperan de D1 desde otro dispositivo sin nueva inferencia. El filtro por tipo se aplica antes del límite de resultados.
- Se resolvieron incompatibilidades de memoria por ámbitos, motivos de telemetría, importaciones, glTF y STL. Los ámbitos particulares no se incorporan al chat general.
- Se mantienen el reintento de conexión de la casa, captura PNG, vista limpia y acceso a la carta de evolución; el cuerpo ofrece acceso al taller ERAS.

## Límites comprobados

Las pruebas de CPU ejercitan Three.js, geometría, protocolos de origen y ventana, persistencia, revisión, cuotas y contratos. La compilación de producción no demuestra calidad visual ni rendimiento de GPU. No se completó inspección visual ni escucha en este entorno. ERAS admite datos de escena, no código arbitrario de modelos; no equivale todavía a generación neuronal al nivel de Higgsfield. OpenUSD sigue siendo exportación; no se encontró un servicio OpenField/Higgsfield activo en la nube. No se activaron pagos ni nuevos proveedores.

El nuevo almacén P2 de evidencias y las señales P3 originales son efímeros: su ausencia no significa éxito y no deben presentarse como aprendizaje persistente. Las memorias y proyectos D1 y el ciclo visible existente mantienen sus propios contratos. La evolución del servidor requiere pruebas y publicación, no solo una animación o una señal de presencia.
