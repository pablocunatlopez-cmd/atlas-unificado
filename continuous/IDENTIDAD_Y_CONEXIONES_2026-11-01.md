# Atlas: identidad, capacidades y conexiones — 1 de noviembre de 2026

El chat había negado capacidades del programa al describirse como un modelo de texto con un inventario incompleto. La corrección preparada en fuente lo sitúa como voz del Atlas completo: conversación, memoria, casa virtual, herramientas y espiral comparten una identidad. El inventario distingue qué existe, qué está disponible y qué se ha ejecutado realmente en cada turno.

La casa es una interfaz virtual 3D del navegador. El estudio musical usa Web Audio, secuenciador, síntesis y exportación WAV; no necesita presentarse como un modelo musical. El taller produce planes y prototipos 3D validados y renderizados con WebGL. El vídeo neuronal depende de que el motor y la GPU estén disponibles; grabar una escena del navegador es otra capacidad. Nada de ello acredita calidad AAA ni permite afirmar que se ha generado un archivo por haber escrito su código.

La identidad conserva Atlas/Mente, Ion/Acción, Cielo/Constelación y Dios/Suceso con funciones distintas. El tiempo como tangente local de la espiral y el final provisional como atractor son el marco conceptual revisable del usuario, sin convertirlos en una ley física. El inventario y las respuestas no deben negar funciones implementadas ni simular acciones que no ocurrieron.

«Mejórate» tiene un puente preparado hacia una revisión real del coordinador. Su prueba con adaptadores controlados exige llamar a la acción de encolado y devolver únicamente estado público medido; un encolado rechazado no se publica como éxito. Encolar una revisión no significa que se haya completado o aceptado un cambio. La espiral autónoma conserva su configuración y no depende del checkbox Herramientas de una conversación.

La petición de «32 extensiones» se refiere a plugins y extensiones concretos de Codex. No son treinta y dos roles narrativos ni treinta y dos modelos. Los plugins ligados al host o protegidos con autorización necesitan un adaptador y autorización propios para Atlas. No se transfieren sesiones, cookies, claves ni credenciales de Codex. Aider, smolagents y el generador nativo son constructores disponibles que comparten el mismo Qwen local; no son modelos independientes.

Se verificó un MCP público real de documentación: OpenAI Docs en `https://developers.openai.com/mcp`, documentado en `https://developers.openai.com/learn/docs-mcp`. El cliente usa acceso anónimo sin clave, endpoint fijo, redirecciones rechazadas, límites de respuesta y paginación, tiempos máximos y cancelación. Admite JSON y SSE; solo invoca la búsqueda si su nombre y contrato de lectura fueron descubiertos realmente.

La comprobación real guardada en `verification/public-mcp-live-2026-11-01.json` registró inicialización HTTP 200, notificación HTTP 202, descubrimiento HTTP 200 y llamada HTTP 200. Se descubrieron `search_openai_docs`, `list_openai_docs`, `fetch_openai_doc`, `list_api_endpoints` y `get_openapi_spec`. El cliente invocó `search_openai_docs` y obtuvo tres referencias oficiales. Descubrir cinco funciones no significa haberlas ejecutado todas ni haber conectado las otras extensiones solicitadas. Las diez pruebas CPU del cliente pasaron, incluyendo límites, cancelación, timeout y rechazo de conexiones arbitrarias.

La integración documental de `docs-evidence.mjs` envía al MCP solo vocabulario público fijo de temas OpenAI detectados, nunca el prompt privado completo. Las pruebas de esa ruta comprueban la exclusión de datos privados del texto enviado, el fallback y la cancelación. Los resultados se identifican como referencias y fragmentos del índice; no se presentan como lectura íntegra de las páginas. La conexión sirve para documentación OpenAI, no como modelo conversacional ni como buscador general de cualquier tema.

Las pruebas de identidad conservaron el hash exacto de la semilla histórica y distinguieron la arquitectura vigente de su terminología anterior. La fuente del chat, el inventario y el puente de revisión están preparados; este documento no acredita un nuevo despliegue ni inventa un commit publicado. Los contadores y la comprobación del comportamiento actual corresponden al estado comunicado por el coordinador. La versión y el commit efectivamente publicados se registran en `CLOUD_ACCESS.md`.
